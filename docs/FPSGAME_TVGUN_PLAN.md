# FPSGame 接入 TVGun：调研结论与成品计划

日期：2026-11-05。用户已确定方向：沿用 FPSGame 的 3D 关卡与战斗，接入 TVGun 手机光枪。

本轮范围：核对源码、恢复本机构建、建立验证基线、制定实施与验收计划。除构建路径修复外，尚未实施游戏功能。

## 1. 结论

以 `D:\FPSGame\game` 为游戏主工程，以 `D:\tvgun\android` 为手机输入工程。复用 Godot/C# 战斗、四关内容、模型动画、音效、存档和调试工具；新增 TVGun 原生坐标输入、定位画面合成和街机操作流程。

不需要重写 3D 游戏框架。核心工作是把“屏幕坐标型光枪”可靠地接入现有游戏，并把手机端操作贯穿菜单、剧情、战斗、暂停、续关和结算。

首版交付单枪 Windows 游戏。鼠标/键盘保留为开发与应急输入；已有双路姿态设备能力保留，但双 TVGun 手机接入不属于首版验收。《纸灯城》已有文档和美术资产留作独立项目，不混入这款游戏。

## 2. 已核实的基础与限制

### 游戏工程

- 源码基线：`D:\FPSGame`，commit `2edac5c`。
- `project.godot`：Godot 4.8 dev、C#、逻辑分辨率 1280×720，实际渲染器为 Compatibility。
- 入口：startup → menu → 选关/连接页 → loading → 关卡。
- 实际关卡映射只有 L1–L4；选关/存档保留了原作 13 关结构，不能据此声称已有 13 关。
- 战斗已含波次推进、镜头切换、怪物对象池、Boss、身体/头部/护甲判定、投射物拦截、补给、暂停、续命、弹尽补给和胜利。
- 已实现的枪为 AK、M4、手枪；配置中的 `gun_type_num=7` 不代表七把枪均已制作。
- 存档支持临时文件替换、备份及损坏恢复。已有 F3–F7 诊断、截图及对象报告。
- `AimState.Screen()` 和 `FireSystem.UpdateSide()` 已支持屏幕点瞄准：相机射线确定目标，枪口转向目标，再用实际枪口射线判定。应沿用并验证这套枪口/激光/命中一致性。
- 菜单接入不能只改战斗的 `GetRightAim()`：`MenuScreen`、`LevelChooseScreen`、`DeviceConnectionScreen` 的部分可用性/点击路径仍依赖 `MouseGun`，`GunUiController.OnTrigger()` 仍按四元数求射线。
- `LevelBase.TriggerVictory()` 会写星级，但传入的 score 为 0；默认关卡存档还是原作全三星/得分 3/排名 1。完整结算与进度需要重新整理。
- `RELOAD` 没有现成的弹匣系统可直接调用：当前是总弹药池，右键和设备第二按键的语义是换枪。

### TVGun 输入工程

- 源码基线：`D:\tvgun`，commit `ce79d01`。
- 坐标规范：1920×1080，追踪器约定以定位白框外缘为四角；手机端已做陀螺预测，默认提前 90ms。
- 坐标以约 120Hz 发送。HTTP 模式为 UDP `x,y` 到 8000，开枪 POST `/shot` 自带 x/y；UDP 模式为坐标与 ASCII 事件同发 9000。
- 现有事件：`SHOT`、`RELOAD`、`COIN`、`START`、`EXIT`。UDP 的 SHOT **没有坐标**，尽管手机 `fire()` 已计算开枪时坐标，该数据没有进入 UDP 事件包。
- 默认事件模式是 HTTP；不能只实现 UDP 而让现有默认设置不可用。当前 Python 打鸭子端也不处理投币等四个控制端点。
- 失锁时手机停止发送瞄准，没有显式 LOST；不能把短暂沉默理解为仍能用旧瞄点开枪。
- 现有发现逻辑在 `startDiscovery()` 启动时按 server 端口 +1 计算发现端口；常见配置为 8001。发现更新 server 不会同步 udpPort。新游戏需要兼容 8001，并明确区分发现与业务端口。
- `Tracker.java` 当前边缘内侧暗度检测仍用固定相机像素 `INSIDE_OFF`，亮画面会影响采纳边线；失锁重采集还有中空亮像素比例检查。
- 当前输入没有按住/释放事件；SHOT 是离散射击，不能当作持续按住扳机，否则会出现一枪连射或跨面板点击。

### 本机引擎与构建

- 已复制到 `D:\FPSGame\godot`，实际版本输出：`4.8.dev.mono.custom_build.9c776068d`。
- Mono 编辑器、GodotSharp、4.8.0-dev 本地 NuGet 包和 Windows Mono release 模板均存在。
- 本机 .NET SDK 9.0.100，具有 .NET 8 运行时。
- 已将 `game/NuGet.config` 改为 `../godot/bin/GodotSharp/Tools/nupkgs`，发布模板改为相对路径，移除这两处对 G: 盘的依赖。
- 实际 `dotnet build` 已成功，0 错误、11 个可空引用警告。首次 headless 编辑器资源导入已成功；存在原有资源路径大小写警告。
- 运行基线测试及图形截图的最终结果见本文末尾验证记录。自动自检不等于手机实机、显示器/电视追踪或完整人工通关。

## 3. 成品边界

交付一款可在 Windows PC 接电视游玩的单枪 3D 街机游戏，包含：

1. 启动、连接/定位引导、可跳过教学、主菜单、四关和难度选择。
2. 手机瞄准射击控制所有必要界面；投币、开始、换弹、退出都有明确反馈。
3. 四关正常战斗、各关 Boss、失败/续关、关后结算、下一关、最终通关入口。
4. 显示器/电视配置、白框尺寸与画面适配、瞄准偏差校准、音量与本地存档。
5. 断线/失锁反馈与恢复，误操作防护，桌面鼠标回退。
6. 可直接启动的发布目录、一键启动入口、版本号和简明接枪说明；在交付 EXE 上复验。

首版默认本地免费游玩，保留可选择的街机投币模式。免费模式不因金币或耗尽总弹药把玩家卡在付币界面；街机模式统一入场/续关扣币规则，并由手机 COIN 增加额度。两种模式均复用战斗内容。

## 4. 技术方案

### 4.1 独立 TVGun 输入源与主线程事件队列

新增 `TvGunProtocol`（纯解析）、`TvGunServer`（网络收发）、`TvGunSource`（会话/有效瞄准/离散事件）、`ScreenCoordinateMapper`（坐标映射）。统一接入现有 InputRouter，新增明确 TVGun 模式。

网络线程只能解析和投递事件，不能直接改 Godot 节点、存档或场景。瞄准流只留最新有效样本；射击/控制命令有界排队，记录接收时间、设备会话和场景代次。切场景/弹出新面板时消耗旧事件，防止一发同时启动游戏和射击、退出后又击中新菜单。

TVGun 会话选择后，短暂失锁不自动切到鼠标瞄点。鼠标回退需显式切换或用户实际选择，避免手机断线后悄悄在桌面光标处开火。暂停时网络和必要的 UI 输入仍处理。

### 4.2 协议：先兼容，再补足射击可靠性

- 兼容当前 App：UDP 9000 文本包；UDP/TCP 8000 的瞄准和 HTTP 事件；UDP 8001 发现应答。若 server 为自定义端口，明确发现配置，不能隐含要求手机自己改成 9001。
- 所有入口转成相同的域事件，防止双通道重复执行。HTTP 请求只有主线程处理成功后才返回成功状态，并有超时和队列上限；状态端点兼容手机 `syncScore()`。
- 旧无坐标 SHOT 只允许使用本设备最近 100ms 内收到的坐标；0.6s 隐藏准星。此兼容限制无法完整解决丢包/乱序，不能作为最终可靠性验收口径。
- 正式协议需版本号、随机启动会话 ID、递增序号、瞄准等级及显式 LOST；SHOT 包自带开枪瞬间 x/y 和对应采样序号，不能改用稍后到达的瞄准。
- 射击按事件去重，一次接受只产生一发并遵守武器冷却；不重试已经过时的射击，不把 SHOT 拉成长按。
- 投币/开始/退出等改变状态的命令加命令 ID、确认和有限重试，服务端按会话去重；过期命令、旧场景命令不能在恢复连接后执行。手机与 PC 不直接比较绝对时钟，接收超时用 PC 单调时钟；必要的客户端命令寿命只比较同一客户端时基。
- 输入 LOST 后立即隐藏准星和禁用命中；新旧瞄准/LOST 按采样序号排序。迟到 SHOT 单独去重，但不得越过已知失锁、场景切换或会话重置的有效性屏障。
- 首版绑定一台手机，其他设备不能覆盖该玩家的坐标；更换手机通过连接页释放绑定。

### 4.3 全局定位画面与坐标映射

全局游戏壳负责外黑边、纯白定位框、内黑安全带、16:9 游戏画面和状态提示，覆盖菜单、loading、剧情、战斗和结算。定位框在内容后处理之后合成，不能被闪光、调试层或过场遮挡。

继续使用 1280×720 游戏逻辑画布，保留原 UI 和相机比例。定位规范框采用 1920×1080；白边初值 24 规范像素、内暗区初值 48，外黑边按显示配置保存。数值来自现有计划，仍需实机确定。

示例：在规范框内留出 72px 四周安全区后，可用矩形为 1776×936；其中居中放入 16:9 游戏得到 1664×936，即 `[128,72]–[1792,1008]`。输入先在白框规范空间校准，再通过实际游戏矩形映射：`u=(x-128)/1664`、`v=(y-72)/936`，游戏逻辑点为 `(1280u,720v)`。实际运行使用配置计算矩形，不把示例常量散落在关卡脚本中。

外黑边不进入白框规范坐标；白边、黑带、信箱区和离屏射击不能钳到游戏边缘目标。窗口尺寸/显示器变化需重新计算映射。根视口与 UI 内部 SubViewport 各做一次正确映射，避免重复 stretch 逆变换。

注意：现有 `run_tv.py.norm_to_px()` 按其内部游戏矩形映射，而追踪器文档约定是白框外缘。必须用九点靶实测查清现存偏差，不能原样复制该函数再用额外偏移掩盖。

### 4.4 明亮 3D 画面的追踪适配

第一优先级是稳定定位，不能等到四关接完再处理。选菜单、天空/窗户、Boss 特效、字幕/HUD、受击效果等最亮帧做持续追踪与冷启动/离屏回屏实验。

内容区可配置亮度限制，并保留局部枪口/爆炸反馈，避免全屏纯白效果。初值可沿用已有设计的 sRGB Y′ 上限 75%，但它不是实机有效性的保证。

若固定 INSIDE_OFF 导致暗度采样进入游戏内容，则 Java/Python 两份追踪器同步改为：按已知白边和内暗区宽度，通过单应逆投影选择暗区采样点。屏幕布局参数通过协议配置告知手机，不能只改游戏端。

重采集的中空检查单独验证。现有黑底鸭子录制只能证明回归，不能证明亮 3D 画面可锁；必须新增亮画面录制，按 WORKFLOW 核对 App 版本与数据格式。

### 4.5 按键与玩法语义

- SHOT：菜单/面板触发一次按钮；正常战斗发射一次，冷却中给出统一处理；开场禁火。所有路径使用同一事件坐标。
- START：待机/菜单进入单人流程；剧情跳过；暂停恢复；结算继续；正常战斗中不重复建局。
- COIN：街机模式增加本地额度并落盘；免费模式提示免费游玩。不能与续关按钮同时扣两次币。
- RELOAD：正式版本实现实际弹匣装填，不得冒充原作换枪。保留原有总弹量/补给作为储备资源，装填只转移弹药、不凭空增加；暂停、开场、死亡与装填中重复请求有明确规则。首版弹匣容量/装填时间按三枪配置化，调参后实测节奏。
- 换枪：通过可枪击的 HUD 武器按钮提供入口，保留 PC 右键，手机无需新增硬件按键。
- EXIT：手机已有双击保护，PC 按状态返回/打开离场确认；战斗退出确认、返回菜单和关闭程序分别处理。

当前只有离散 SHOT。首版每次按枪一发；若后续需要 AK/M4 按住连射，再新增 DOWN/UP + 释放超时协议，不能根据两个 SHOT 之间的间隔猜测按住状态。

### 4.6 进度、结算与打包

四关列表与实际资源一致，隐藏不可玩的后九关。新存档按首关开放、后续通关解锁；调试全解锁与玩家进度分开。保留独立 TVGun 用户目录和存档版本迁移，不覆盖参考版本的玩家存档。

增加本局击杀、命中/有效射击、弱点命中、耗时、受伤和续关统计；离线结算显示真实数据并保存最高成绩，不展示虚构在线排名。后续关卡与最终通关从结算可直接继续。先验证现有免费/金币数值，再调整装填带来的平衡。

发布目录必须包含 EXE 及匹配的 C# 数据目录，不能只复制 EXE。交付可复现构建命令、启动脚本、版本/提交标识和防火墙端口说明。使用实际发布包验证，不能只验编辑器。

## 5. 实施顺序与阶段验收

### P0：恢复环境与游戏基线

工作：确认匹配引擎、修复路径、导入资源、编译；执行菜单/输入/真实射击/四关自检，查看代表性渲染截图；记录原有问题。

验收：工程可在 D: 盘构建运行；自检结果与限制有记录；编辑器、SDK、发布模板版本一致。当前已完成构建和导入，测试结果见末尾。

### P1：定位画面与输入贯通，先打一只怪

工作：建立游戏壳、九点靶与坐标映射；旧 UDP/HTTP/发现兼容；TVGunSource 接入菜单和 L1；SHOT 单次消费、失锁/断线门控；升级带坐标/会话/LOST 的正式协议。

验收：同一手机可瞄准点菜单、进入 L1、打中/打空/耗弹；一发只结算一次；离屏、LOST、乱序与旧会话不产生幽灵枪。明亮菜单与 L1 能冷启动定位并离屏恢复。

**阶段门：P1 的真机亮画面追踪不通过，先解决定位，不继续扩充四关适配。**

### P2：完成所有光枪操作流程

工作：连接引导、偏差校准、START/COIN/RELOAD/EXIT 状态行为、可射击武器按钮；统一输入所有者、暂停/断线与恢复；免费/街机模式。

验收：从开机到失败/续关/返回可只用手机操作；掉线不丢档、不积压射击、不反复扣币；装填/换枪/补给三者语义明确。

### P3：四关成品流程与结算

工作：逐关检查开场、机位、敌人、弱点、弹药、Boss、失败/胜利；修复进度默认值，补真实统计、下一关与最终通关。按 TVGun 实际命中反馈调整三枪节奏。

验收：实际手机以正常模式连续完成四关；每关可失败、续关、重试和退出；关闭后进度/最高成绩仍在。自动击杀自检不能代替此项。

### P4：显示器/电视实测与 Windows 发布

工作：两类显示设备的布局/亮度/预测配置；最亮内容追踪录制、长时间游玩、重连、焦点切换、损坏存档恢复；导出及发布包复验。

验收：1080p 与 4K 坐标正确，定位框完整；各场景无阻塞流程；另一目录可启动；版本可核对；一键启动与手机设置说明齐全。

## 6. 验证口径与优先风险

自动验证覆盖：正常/畸形/NaN/越界包，乱序/重复/过期包，会话重启，LOST 屏障，单事件单次操作，命令去重，窗口/内容坐标往返，暂停与加载时输入，实际射线命中，弹匣弹药守恒，存档与进度。

图形验证覆盖：菜单、连接页、明亮 L1、L2/Boss、L3/L4 特效、装填/暂停/续关/结算；检查框不被遮挡、HUD 安全区、枪口/激光/命中位置。

硬件验收覆盖：显示器与电视、常用距离、主摄与超广角、九点慢瞄/甩枪、离屏 0.5/1/3 秒、断 Wi-Fi 与恢复。建议目标为静止九点校准后中位误差 ≤15 规范像素、P95 ≤30；有效可见白框的目标场景采样有效率 ≥99%、回屏重锁 P95 ≤1 秒。以上均为待实测目标，需固定距离、镜头、显示模式和样本量，不能声称当前已经达到。

手感延迟同时测网络接收间隔、游戏帧时和实际端到端延迟；120Hz 上报不等于 120Hz 渲染，也不等于 8ms 端到端延迟。PC 端先不追加预测，避免与手机 90ms 预测叠加。

优先风险依次是：亮画面追踪失败；开枪坐标/视口映射偏移；离散事件被当作长按；旧 UI 输入分支漏接；新增弹匣改变难度；素材分发范围和字体来源。现阶段以本地自用为目标，外部分发前再清点素材授权和替换不可分发字体。
