# GunForge 通用关卡设计引擎开发任务

版本：v0.2 · 2026-11-08 · 状态：**用户已授权全自动执行；实际进度以 [execution_state.json](../gunforge/level_design/reviews/execution_state.json) 为唯一来源**。

依据：[方案 v0.3](LEVEL_DESIGN_ENGINE_PLAN.md)、[v0.2 复审](REVIEW_LEVEL_DESIGN_ENGINE_PLAN_v0.2.md)。本文件把方案拆成可执行批次；用户 review 后另行指示开始开发。任务文档通过不代表任何候选关卡已被采用，也不替代各阶段验收。用户后续明确授权自审后全自动执行，取代本文原有的逐阶段开工确认；实际用户体验、试听与真机验收不能由此冒充完成。

## 1. 交付目标与边界

交付一个跨游戏的 2D 定点光枪关卡设计闭环：Agent 从设定和可用能力设计/修改关卡，编译和运行，用户在工具中查看、播放、批注，Agent 提交新候选，用户明确采用或回退。

首版必须同时证明：

- 《纸灯城》巷口从硬编码迁移为规则/内容包，已知缺陷独立处理。
- 抽象靶场无生命、无敌人攻击的配置可执行，不能被强制套用本作流程。
- 科幻保护/拦截白模可执行，包含第三种规则组合与任务分支。
- 三者共用核心、2D 适配、编译、运行、回放、审阅与版本流程；公共核心不按游戏 ID 分支，工具不为每款游戏复制一套页面。
- 工具只读设计数据，允许播放控制、批注和采用；设计修改由 Agent 完成。

暂不实现 3D、踏板/舵轮、双枪、持续扳机协议、在线动态编关、完整三关美术生产。复杂 Boss、墨线连锁和工具内置模型调用列入后续批次，不计入本文件的首版完成条件。

## 2. 执行规则与证据

### 2.1 任务状态

任务初始状态为 `not_started`；当前状态只维护在 execution_state.json，本文件不重复维护状态表。执行时每项依次记录 `in_progress → implemented → verified`；需要用户判断的阶段另记 `awaiting_review / accepted / revise`。不得把“代码写完”当验收通过，也不得由 Agent 自行写入用户采用。

每次续接任务先读取本文件、对应方案章节、任务实际产物和最新状态；保留前序结果，从第一个未完成且依赖满足的任务继续，不重跑全部检查或重做已批准决议。任务依赖允许调整实现细节，不允许隐式扩大首版范围。

### 2.2 目录与产物（部分已建立，按任务逐项落地）

- `gunforge/level_design/specs/`：schema、时间/输入/空间/公共轨迹等技术契约。
- `gunforge/level_design/rulesets/`：版本化规则定义；g01 引用现有 bible，不复制权威数值。
- `gunforge/level_design/packages/<package_id>/revisions/<source_revision>/`：不可变的小型候选源、锁文件与设计说明，入 Git。
- `gunforge/level_design/adopted/<package_id>.json`：当前采用源版本指针，入 Git；不维护第二份“当前可编辑源”。
- `gunforge/level_design/reviews/`：小型批注、决议、采用理由与证据索引，入 Git。
- `gunforge/framework/`：运行器与适配；通用核心、2D 几何、外壳和 g01 扩展分开。最终模块名在 LD00/LD09 定义，不在此假装已经落地。
- `gunforge/pipeline/level_design/`：构建、检查、录制、回放、证据与候选管理入口。
- 默认外部目录 `D:/gunforge_cache/level_design/`：基准、build、完整轨迹、截图/音频和 QA 运行产物；通过配置改根路径，代码不写死 D 盘。

Git 内报告索引包含路径/URI、内容哈希、source_revision、build_id、输入/提交序列哈希、运行器/引擎版本和重现命令。生成物不新增进 Git；不删除现有报告、审核资产或录制。采用依赖可恢复的候选源，不依赖只存在于外部缓存的 JSON。

### 2.3 每项完成必须留下

任务 ID、实际变更文件、所用前序版本、命令/退出状态、测试摘要、证据索引、已知限制和下一任务。预期失败用例要记录拒绝原因，不能只统计退出码。涉及画面的任务同时保存玩家画面与调试叠加；涉及声音需记录 cue 时间并实际试听代表片段。

所有新契约测试关注可观察结果、边界与错误恢复；不以重复实现细节的断言凑数量。确定性轨迹中剔除墙钟、性能计数等非语义字段，固定字段顺序/数字编码、事件顺序及算法版本。A1c 对照的是统一公共行为轨迹，不是两个实现的私有内存结构。

本仓库已有其他未提交文件。实施时只处理任务相关路径；采用提交或候选提交不得 `git add .` 打包其他工作，不能为清理状态丢弃用户改动。

## 4. 阶段依赖与规模初估

顺序：**LD00 → A0（LD01–03）→ A1a（LD04–06）→ A1b（LD07–08）→ A1c（LD09–13）→ A2（LD14–16）→ B（LD17–19）→ C（LD20–23）**。

阶段内部依赖写在各任务；依赖不满足不能提前标记完成。A1c 的合同草案可供前序讨论，但通用化代码不得混入 A1a 的等价性验收。

初估以单条研发工作流的有效研发日为单位，包含实现、自测和一次返修，不含等待用户/硬件、全新正式美术、外部环境故障或额外机制。不是 AI 的运行耗时预测或交付承诺：

- A0：1–3 日；验收门 G0。
- A1a：4–8 日；验收门 G1a。
- A1b：1–4 日；规则等待时间另计；验收门 G1b。
- A1c：8–15 日；验收门 G1c。
- A2：4–8 日；验收门 G2。
- B：2–3 日形态原型，选定后 8–15 日；验收门 G3。
- C：6–12 日加真实设备时间；验收门 G4。

合计约 34–68 个有效研发日量级，LD00 review/决议时间另计。A0 与 G1a 后依据实际变更量、失败数和返工重新估算；不得用原估计逼迫跳过验收。实现耗时达到该阶段上限仍未通过时，输出瓶颈、剩余项与缩减方案，交由用户决定继续或调整。

止损不是降低泛化要求：不能删除第二白模、绕过统一运行器，或把回放改为仅播放视频后仍宣称原目标完成。

## 5. LD00：冻结执行基线与决议记录

- **依赖**：用户 review 本任务文档，并明确开始范围。
- **工作**：确认方案/任务版本、授权批次、源与生成物目录；整理 D01–D10 的来源、旧行为、计划处理及决议状态；固定首版能力列表和暂不实现项；给技术契约待验证参数分配责任任务。
- **交付**：`reviews/implementation_decisions.json`、阶段状态记录、能力覆盖清单初版。用户选择与技术建议分栏记录。
- **验收**：每个未决项都可定位到受阻任务；未决项没有被写成 approved；所有 LD 任务保持真实状态。后续任务能在不猜规则的情况下开始。
- **不做**：改游戏行为、制作新素材、开发完整框架。

## 6. A0：旧基准

### LD01：保存可恢复的旧实现和环境

- **依赖**：LD00。
- **工作**：记录 Git HEAD、工作区补丁、相关未跟踪源、引擎/依赖、实际素材/运行包哈希；保存原始旧实现快照，核对 LFS 真实内容。新基准目录不得覆盖已有 0B 报告。
- **交付**：`reviews/baseline_source.json`、外部原始快照及恢复说明、完整性检查结果。
- **验收**：另一个隔离目录可按索引恢复并启动同一旧版；资产哈希一致。不能只记录 HEAD 而漏掉工作区差异。

### LD02：隔离输入的录制控制器

- **依赖**：LD01。
- **工作**：建立 record-only 运行方式或等价隔离 harness，屏蔽鼠标/键盘、UDP、HTTP 实时玩法入口，仅接受控制器显式注入。设备锁定/会话状态也由受控记录驱动；记录完整 freeze/step/input/模式/刷新/截图操作及响应。插桩仅加隔离、观测与控制，保存独立补丁，不改 advance/command 的玩法计算。
- **交付**：录制脚本、序列格式、插桩补丁哈希、实时输入隔离证明。
- **验收**：录制时故意发送外部射击/控制包和桌面输入，轨迹无变化；控制器注入仍走原游戏入口。step(9) 与 step=1×9 的刷新语义区别明确记录，默认边界使用 step=1。捕获失败会报错，不登记为截图成功。

### LD03：录制并复核旧行为集

- **依赖**：LD02。
- **工作**：覆盖正常通关、漏打一只、纸身误射、空弹装填、失锁恢复、死亡续关、D02 连续救援射击、D03 重复打激活源；保存事件、公共状态、输入/步进/几何刷新序列和关键帧。两次受控运行验证稳定性，人工抽查输入与画面。
- **交付**：小型 `reviews/baseline_cases.json` 索引、外部完整证据、A0 对齐字段及事前允许的边界 ±1 tick 说明。
- **验收 G0**：基准可重放且无额外输入；分数/生命/命中/对象状态精确可比。D02 未复现时登记事实及原因，不伪造失败证据。用户无需先选灯时长才能保存旧行为。
- **未通过**：修录制/隔离，不开始改运行循环；G0 未完成不能对后续结果声称“与旧版一致”。

## 7. A1a：确定性改造，保留旧语义

### LD04：固定步长与统一输入队列

- **依赖**：G0、LD00 的技术起点记录。
- **工作**：固定模拟步长加累加器；所有输入排队，保留会话、序号、接收顺序、目标 tick；暂停、失锁与墙钟超时分开；调试输入走同一消费路径。输入积压、最大追赶步数和舍弃策略必须显式记录，不因低帧率静默丢掉战斗时间或延迟补发陈旧射击。
- **交付**：时钟/输入技术契约、运行循环改造与队列边界用例。
- **验收**：固定序列在不同帧率/追赶负载下事件顺序稳定；暂停不推进战斗截止；旧包时效、去重与 LOST 屏障不退化。不在此任务重写关卡 JSON 或修 D02/D08。

### LD05：姿态、命中几何和等价空间计算分离

- **依赖**：LD04。
- **工作**：从 scene/update_frame 拆出纯姿态/几何计算；D10 采样使用同一冻结资源、变换、阈值和渐变规则搬到逻辑层。落地 LogicPose、RenderSubmission、InputBinding、SubmissionSchedule；主线程入队绑定，维护有界引用缓冲。绘制只读；首版交互对象不做仅视觉插值。
- **交付**：姿态/提交格式、CPU alpha 查询、等价空间采样、缓冲策略与命中解释基础记录。
- **验收**：无窗口可生成相同形状与受击许可；移动跨 tick、30Hz 跳帧、144Hz 重复提交、同 tick 多枪、尚无提交、姿态过期、目标已解除威胁、截止边界均有明确结果。输入不能换绑当前几何；无有效姿态不产生命中或耗弹。D10 的允许差异仅限事先登记边界。

### LD06：规范轨迹、基础快照与等价性验收

- **依赖**：LD04、LD05。
- **工作**：建立公共行为轨迹（输入/事件/资源/区域结果/姿态/任务/会话），剔除非语义字段；记录随机数版本与状态，支持无窗口运行和快照恢复。将 A0 字段映射到新轨迹，不事后放宽容差。
- **交付**：轨迹 schema、比较器、重复运行/帧率矩阵、耗时与内存初测、A1a 差异清单。
- **验收 G1a**：相同包/seed/输入/提交计划三次哈希一致；30/60/144Hz 的逻辑轨迹一致；A0 对照只存在预登记 ±1 tick 边界，分数/生命/命中一致。不同提交计划的运动命中差异能由 InputBinding 解释。
- **未通过**：只定位确定性/几何改造，不开始数据化。若成本超上限，向用户提交瓶颈与回放精度方案；不自行改为不可回放或仅视频预览。

## 8. A1b：独立缺陷与参数决议

### LD07：复现并独立修复 D02、D08

- **依赖**：G1a、LD00 对缺陷修复的确认。
- **工作**：各自先在 A1a 下复现，再修复；D02 在逻辑层一次性完成/结算，与消散动画是否仍可见无关；D08 按 g01 契约只扣分、不扣生命。每项独立变更，避免混入通用核心重构。
- **交付**：两项失败前/修复后输入与证据、预期公共轨迹差异、回归用例。
- **验收**：重复射击不重复加分/重置获救动画；误射纸身生命不变；正常威胁伤害仍有效；无关基准轨迹不变。若 D02 原路径无法复现，先缩小问题、补守卫决议及证据，不能报告“已复现”。

### LD08：完成 D01–D10 决议并固定修正基准

- **依赖**：LD07；涉及数值变化的子项另依赖用户决议。
- **工作**：D01/D03/D07 按明确选择改变，不选择则保留 migration_legacy；D04/D05 核对坐标、尺寸、预警及审批来源；D06 显式化前先记录现状/目标 clip cue；D09 明确目标时长；汇总 D10 等价性。每项变化单独比较。
- **交付**：完整差异登记、修正后 g01 固定步长基准、未决项及影响范围。
- **验收 G1b**：每个变化都有唯一决议及预期轨迹差异；未决项明确标 legacy，正式 g01 放行受阻但无关核心不受阻；无关用例精确不变。
- **未通过**：保留固定语义基准，不让 A1c 同时“修问题+通用化”；需要改变玩法时回到本阶段登记。

## 9. A1c：最小通用核心与两个规则包

### LD09：源格式、编译器、锁定与 source map

- **依赖**：G1b（允许显式保留未决参数）、LD00。
- **工作**：以 g01 和靶场实际需求冻结最小 JSON Schema；ID 键集合、显式顺序、毫秒域量化、source map、文件边界、引用/能力/单位验证；定义 source_revision 和 build_id，锁定 schema、规则、资源、引擎/编译器与算法版本。相对链不逐段取整，自身清单和 Git commit 不进入源 hash。
- **交付**：`specs/`、编译/检查入口、两包最小源草案、支持状态清单。
- **验收**：同源生成相同规范产物；插入事件不使 ID 补丁漂移；跨文件缺失/错误单位/无界循环/可静态证明不可达/量化零窗口被明确拒绝；空间依赖的未知可达性不伪报结构证明。缺资源占位与缺行为实现处理符合方案。

### LD10：通用实体、事件、条件/效果与空间查询

- **依赖**：LD09、LD05。
- **工作**：将需要的实体/组件、任务/分支、行为窗口、资源/评分、状态与类型化效果实现为最小核心；注册区域包含、冻结 mask 采样和距离查询，带空间/算法/阈值来源；玩法查询用当前 LogicPose，命中用绑定姿态；任务/拾取/奖励幂等，别名不重复结算。
- **交付**：核心操作与查询注册、版本/序列化/审阅元数据、bible 引用解析及规则约束适配。
- **验收**：g01 激活源范围影响可声明式表达；靶场进入区域触发计时；更换题材不改核心；条件依赖循环、未注册插件、跨空间错误、缺查询实现明确失败。无任意 eval、无按 g01 判断的分支。复杂重叠/可见性未完成时标未启用，不用 AABB 代替 alpha。

### LD11：正式运行契约、会话外壳和可配置 HUD

- **依赖**：LD09、LD10。
- **工作**：定义并接入加载/注入/步进/公共状态/姿态提交/快照/重试/退出契约；外壳负责生命周期和暂停原因集合，规则包声明流程与 HUD 字段，设备适配负责连接校准。去除主入口对 lives/ammo/user_paused 等 g01 字段的直接依赖。
- **交付**：运行接口契约、外壳与 g01 兼容桥、可配置 HUD 数据结构。
- **验收**：生命制与无生命制均有开始/暂停/结果/退出；无续关功能的包不显示续关，不要求伪造生命/弹药；HUD 不改逻辑；多个暂停原因解除顺序正确，关闭设置不能清除失锁暂停；网络在暂停期间仍能恢复。

### LD12：g01 数据/规则包迁移

- **依赖**：LD10、LD11。
- **工作**：将位置/轨迹、出现、空间源、目标许可、救援、道具、计分、动画/音效/提示、转场迁入规则与内容包；保留 bible 哈希和 g01 命名空间。统一语义事件绑定 cue，D06 的动作时长/cue 按决议处理。
- **交付**：完整巷口包、迁移字段与 source map、同素材运行入口、A1b→A1c 比较结果。
- **验收**：与 G1b 公共行为轨迹逐 tick 精确一致，不使用 ±1 tick 容差；内部状态可不同，但公开事件/资源/区域值/姿态一致。存在有意玩法调整时退回 LD08 另行固化基准。只改数据即可改变时序/位置/预警/cue。

### LD13：抽象靶场实际运行与跨包验收

- **依赖**：LD10、LD11；G1c 汇总另依赖 LD12。
- **工作**：用简单几何/白模创建第二包：静止/横移目标、正确/错误类别、限资源/限时、得分目标、无敌人攻击/无生命、进入区域触发和成功/超时合流。使用非 g01 ID、文案和布局，至少测试一种非 1776×936 的内容尺寸。
- **交付**：靶场包、输入/提交计划、两包编译运行回放结果、公共代码依赖检查。
- **验收 G1c**：靶场可编译、运行、命中、完成/失败并回放；g01 精确对照通过；核心与外壳无游戏 ID 特例；不加载 g01 素材也可用。不同画布下输入/几何映射正确；未知能力不会静默忽略。
- **未通过**：补通用接口再进入 A2，不用仅输出 JSON 的靶场充当泛化证据。

## 10. A2：候选版本与 Agent 最小闭环

### LD14：候选源、隔离构建、采用与回退

- **依赖**：G1c、LD09。
- **工作**：实现源目录/清单锁、ID 补丁的 base/test 校验和原子应用；候选小源入 Git，build/证据外部；版本指针定义唯一采用版，运行器显式加载 build_id；采用有用户记录及限路径提交，候选和当前版同时可启动。实现失败/并发/崩溃恢复。
- **交付**：版本命令/入口、采用事务说明、索引/日志格式和重建脚本。
- **验收**：过期 base、半包写入、锁文件变更、资源哈希错误被拒绝；采用中断不留下半新状态；回退后可重建启动；候选不覆盖既有 runtime 或采用源；无关 Git 修改保持原样。自动测试不能伪造用户采用事实，测试用独立仓库/索引。

### LD15：通用调试预览、证据包与批注

- **依赖**：LD14、LD05、LD11。
- **工作**：将 F1 叠加从 g01 移到通用适配/审阅服务，显示实际 alpha、保护/无效/遮挡和辅助边界，解释每枪绑定姿态/当前许可/结果；自动截图、关键片段、轨迹与差异；批注记录版本、路径/seed、时间、ID、区域、期望和不可变项。此阶段可由聊天提供批注，不先开发完整网页。
- **交付**：直接 Godot 预览入口、证据包与批注格式、处理状态机及双包示例。
- **验收**：g01/靶场同入口，空 alpha 边缘与前景/保护阻断解释正确；AABB 模式明确标粗筛；截图绑定真实提交而非当前逻辑猜测；旧注释失去 ID 时标需重新定位；Agent 不能自行关闭视觉问题或标用户已采用。

### LD16：真实 Agent 修改迭代与 G2

- **依赖**：LD14、LD15。
- **工作**：建立 Agent 任务输入/能力读取/受限补丁/自检/候选输出的可重复流程；先从当前聊天调用，不绑定模型 API。让用户实际批注并迭代两三轮，其中至少一轮靶场；包含“晚出两秒、移动位置、保留另一对象”等约束，以及一个视觉遮挡问题。
- **交付**：输入模板、候选与证据、批注答复、变更范围报告、每轮用户选择和下一阶段建议。
- **验收 G2**：Agent 实际读取图像/检查结果后提交，修改保留不可变项；用户可看差异、预览并明确采用/拒绝/继续；采用前旧版不变。记录失败修正，不能用事先手写的最终 JSON 冒充 Agent 从批注生成。
- **决策点**：用户据体验选择进入 B 或先补规则能力；未经选择不自动建设完整工具。该停点来自本任务范围，非代码故障。

## 11. B：完整审阅工具

### LD17：工具形态对照原型与选型

- **依赖**：G2、用户选择继续 B。
- **工作**：在总计 2–3 日初始预算内，对照 Godot 内界面与网页+Godot 桥接；用同一跳转/批注/只读属性/版本切换用例检验。网页路线必须验证与真实 Godot 姿态/事件同步；不重写命中。不在两种原型都做完整 UI。
- **交付**：可运行的小原型、成本/限制/部署与单窗口结论、推荐路线和用户选型记录。
- **验收**：选择依据来自实际演示，未测项标明；用户确定一条路线后才做 LD19。预算内没有可靠桥接时，说明本机 Godot 方案的可用性与代价，不盲目继续双路线。

### LD18：完整快照、时间跳转与音画恢复

- **依赖**：G2、LD06；可与 LD17 的选型讨论独立，但须在 LD19 接入前完成。
- **工作**：补齐方案快照清单，含空间源/渐变、事件/输入队列、提交姿态引用、随机数、动画/附件、镜头相位、提示/拾取、持续音频重建；支持检查点/每秒快照、向后重放、分支输入记录。跳转不补播历史一次性声音。
- **交付**：快照/恢复版本契约、随机跳转比较器、90 秒基准性能和内存报告。
- **验收**：两个包从快照恢复与从头重放的公共轨迹精确一致；同环境代表帧/遮罩对齐；循环音位置、cue 和字幕不串段。任意跳转 P95≤0.3 秒、无窗口≥10倍实时为原型目标，报告预热/样本量/设备/资源，未达标给瓶颈和决议，不写已通过。

### LD19：只读关卡树、时间轴、事件图与版本审阅

- **依赖**：LD17 选型、LD18。
- **工作**：实现关卡树、真实画面、多轨时间轴、事件图/路径选择、只读继承属性、source map、错误定位、旧/新版本对照、批注锚定与处理日志；播放/逐帧/倍速/循环与检查点控制。条件事件显示相对窗口，未发生时不伪造绝对时间。
- **交付**：选定形态的正式工具、两包审阅示例、操作说明。
- **验收 G3**：任意抽样出怪/攻击/任务/cue 可从画面定位到触发与源字段；不同规则包由元数据展示，不改工具代码；候选/采用版本不混淆；无设计拖拽/参数编辑入口。播放路径、seed、输入记录和版本始终可辨；回放结果与真实运行同一产物。
- **未通过**：补同步/可读性问题，不另建第二战斗模型或每游戏专属查看器。

## 12. C：第三规则包、检查与交付

### LD20：功能机器人、视觉指标与警告处理

- **依赖**：G2、LD10、LD15；工具内展示依赖 G3。
- **工作**：功能机器人优先；补动作成本具名模型、满弹/一发/空弹、状态到期/保护对象遮挡/并发等边界；按实际 alpha/遮挡定义启用重叠及可见面积指标。结构错误/规则硬约束/启发式警告分开；警告确认引用具体版本和证据。
- **交付**：检查器、公共可见信息接口、指标算法定义/阈值来源、能力状态更新和报告。
- **验收**：缺引用/非法能力硬阻断；不可辨识/公平性推断可预览但显式告警；Agent 不自动关闭警告。功能机器人可用内部状态作诊断，但难度决策只用玩家可见信息，不提前瞄隐藏目标；未标定模型不宣称代表人类通关率。

### LD21：投射物/复合任务与科幻保护白模

- **依赖**：LD10、LD11、LD20。
- **工作**：启用二维运动、攻击/可拦截投射物、保护对象、空间触发/重叠、护盾窗口及成功/失败合流；以科幻白模组合为第三包，用不同资源/奖励与表现。新增通用操作注册插件契约，禁止硬编码成 sci-fi 专用分支。
- **交付**：必要模板/查询的正式实现、科幻包、分支输入记录和完整候选/批注样例。
- **验收**：不拦截/拦截、保护成功/失败、护盾内外、超时与重试都可运行回放；三包切换不改核心/工具；任务分支、奖励幂等、检查点恢复正确。至少一次 Agent 修改第三包并可预览，不以静态字段声明算完成。

### LD22：三包集成、显示/光枪和性能验收

- **依赖**：G3、LD20、LD21、g01 正式放行所需决议已解决。
- **工作**：三包全链路回归、并存构建与版本重建；显示器/电视验证坐标、校准、失锁、恢复、离屏换弹及明亮/高特效场景；核对现有手机构建与协议版本，有协议变化时才重建安装并按 WORKFLOW 留录制证据。检查音画、目标可辨识和帧时/内存。
- **交付**：每包通过项/未测项/失败证据、真实设备记录、性能目标处理结论和用户体验意见。
- **验收 G4**：设计、编译、运行、回放、审阅、Agent 候选及采用流程覆盖三包；真实硬件结果单独通过，不拿鼠标/合成图替代。若无法取得设备，可交付软件结果但 G4 硬件项保持待验，不标整体完成；只暂停依赖硬件的验收。

### LD23：可恢复交付与后续开发入口

- **依赖**：LD22 的软件结果；完整最终交付需 G4。
- **工作**：提供启动/构建/检查/录制/回放/候选/采用/恢复命令与文档，注明版本和资源依赖；更新 README/本任务状态/能力清单；确认旧 Demo 对照入口可恢复，临时兼容桥何时移除有依据。整理剩余体验问题及后续机制任务。
- **交付**：一份可重现的交付索引、三包示例入口、开发/用户说明、已知限制与未完成列表。
- **验收**：另一干净目录可按说明重建并启动指定源版本；删除派生 build 后可重建；丢失外部证据可检测；不依赖 Agent 未记录的临时文件/口头知识。首版未实施机制明确列出，不宣传完整街机类型支持。

## 16. 全自动执行期间的自审补充

仓库中新发现的 [任务 review](REVIEW_LEVEL_DESIGN_ENGINE_TASKS.md) 作为核对依据；不将其中的建议开工流程当作对用户全自动授权的覆盖。

- T02：core_tests、实际引擎通关/续关、HTTP/UDP 已纳入 A1a/修复后检查。未修改定位算法，不重复宣称已经完成新真机追踪；涉及边框或追踪变化时再跑相应回放/几何回归。
