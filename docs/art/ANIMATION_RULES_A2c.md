# 纸灯城 A2c：2D 人物动画依据与执行规则

本次起因是 A2b 人审退回：求助手掌左右/掌面错误、动作仍僵硬、求助时仍微笑，墨怪受击偏弱。场景、点灯、人物造型、墨材质与反光沿用。此前数值检查只证明骨骼连接，不能证明掌面、动作表演正确；撤回将其描述为“正确人体运动”的过强表述。

## 查阅的一手资料（2026-11-04）

- [Godot Cutout animation](https://docs.godotengine.org/en/stable/tutorials/animation/cutout_animation.html)：剪纸层级可结合逐帧贴图，绘制顺序应独立考虑；IK 可辅助摆放末端。该页的编辑器 IK 说明不等于本项目已经有运行时 IK。
- [Spine IK constraints](https://esotericsoftware.com/spine-ik-constraints)：区分 FK 与 IK，二骨链有明确弯曲方向；伸缩、软化、混合是独立选项。IK 求解不是解剖正确性的自动保证。
- [Spine Attachments](https://esotericsoftware.com/spine-attachments)：一个槽位可有多个附件，但同一时刻只显示一个，可通过关键帧切换。
- [Spine Tips](https://esotericsoftware.com/spine-tips)：不同朝向/姿势可分别准备附件，再用相应骨架姿态驱动。
- [Spine Graph](https://esotericsoftware.com/spine-graph)：关键帧同时定义时间和值；曲线控制速度变化，离散属性可以使用阶梯切换。

以下是针对本项目的制作决定，不是声称文档规定了通用人体角度或特效强度；也不表示已购买、接入 Spine。

## 固定坐标与左右侧

旧 JSON 的 `_l/_r` 实际按画面左右排列。兼容旧 ID，但明确标记为 `screen_left/screen_right`；本次三分之二正面角色，画面左臂对应角色自身右臂，画面右臂对应角色自身左臂。角色用自身右手求助、自身左手持物。描述、元数据和检查必须一致。

抬起的右手掌面朝观众时，四指向上，拇指在画面右侧。不能旋转/镜像整块前臂假装掌面转换；左右侧、掌/背面与肘关节弯曲是三个独立问题。无掌面翻转的动作不允许矩阵行列式变负。肘角范围只是这个机位的投影约束，不是人类关节的通用医学范围。

## 采用的方案：骨架 + 姿态附件 + 表情附件

保留原十骨架与手持物；为求助增加右掌附件，在原前臂的腕部挂接，原袖口保持；它是附着槽，不新增人体骨骼。担忧/呼救头部与原轻松头部共用颈轴。新增表情、掌面用 GPT 出图，原认可图不覆盖。源图归档，透明边界、缩放、锚点作为可复现的资产装配记录。

FK 控制肩—肘的关键姿势，腕部补充小幅摆动；腿继续使用二骨 IK 固定支撑脚。先检查下垂、抬手过渡、举手、摆手两端、收回等关键姿势，再看整段速度。肩先带动，肘跟随，掌面保持；不靠持续正弦函数摆整条手臂。持物侧不得换手、翻转或脱离握点。

表情由剧情状态决定：受困/求助/受惊使用担忧呼救；获救动作开始仍担忧，确认脱困后才切轻松；感谢使用轻松。不得把笑脸带入人质受困状态。附件切换采用离散可追踪事件，不叠两张脸形成鬼影。精细口型、眨眼和转头方向套件留待后续，不假称已有完整表情库。

## 验证与交付

离线检查覆盖实际渲染所用附件、变换、可见墨及保护区：腕锚对齐、变换不镜像、手掌方向和关键姿态截图、表情状态、不拉伸的骨长、脚固定、接缝、附墨有效面积、HUD/边缘运动范围。人工观察实际掌面与表情，不能用“配置写着 right”作为图像正确证据。保存关键姿势近景与正常尺寸视频，附全帧检查范围和失败历史。

墨怪增加分级的受击停顿、压缩、回弹与局部粒子；普通命中、印迹命中、净化互相可辨。参数是待人审的项目选择。亮度统计读取实际合成帧；不以全屏白闪、提高常驻反光来替代冲击感。仅墨怪可受击，纸居民仍只有 NPC/人质行为。

本轮不放行 A2 全部技术项。深度带亮度、完整隐藏几何、引擎运动与遮挡、阈值标定、追踪筛查、正式引擎和真实光枪待办继续保留；T08 仍需 A2 门槛，T09–T16 批量仍等真实 0B 五项验收。
