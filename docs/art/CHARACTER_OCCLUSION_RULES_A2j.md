# 纸灯城 A2j：人物分件与遮挡规则

版本：`g01-character-occlusion-1`。调研及代码核对日期：2026-11-05。

本规则用于修复当前人物前后遮挡，不是修复完成或人审通过记录。已确认的人物造型、肘部曲线、糖葫芦握点和朝向继续作为基础；遮挡修正后仍须检查它们是否受影响。T07 保持返修，T08 未启动，批量仍等真实 0B 五项验收。

## 一、结论

采用「骨骼负责跟随、绘制槽负责前后、姿态状态负责换层、局部遮罩负责穿插、换图负责转面」的组合方案。没有一张适合所有动作的固定人体层级表。

稳定性的含义是：同一角色、动作时间和状态得到同一份绘制清单；该清单满足明确的遮挡关系；关节和抓握接触处有唯一的像素归属；跨前后的变化经过编排并检查。不能用锚点零误差、骨骼角度正确或排序稳定，替代实际遮挡观感。

## 二、调研依据与适用边界

以下为官方机制；后文的槽位、状态和验收要求是本项目的工程规则，不冒称行业统一规范。

1. **骨架层级与绘制层级应分开。** Spine 使用独立的 slot 列表控制绘制，slot 依附骨骼，但不受骨骼父子顺序限制；同一骨骼上的附件可以分别处在另一骨骼附件的前后，绘制顺序可以打关键帧。[Spine Slots](https://en.esotericsoftware.com/spine-slots?lang=en)
2. **同一槽位只显示一个姿态附件。** 适合把不同掌面、不同头部姿势放在同槽切换，而不是将两张完整手或脸同时叠放。[Spine Attachments](https://en.esotericsoftware.com/spine-attachments)、[Spine Slots](https://en.esotericsoftware.com/spine-slots?lang=en)
3. **前后跨越可以是动画事件。** Godot 的 cutout 教程用“从背后拿东西到身前”说明深度变化，并介绍 Behind Parent；当前 CanvasItem API 仍提供该属性及 z_index。教程标注尚未全面更新至 4.7，具体实现以实际引擎版本和 API 为准。[Godot Cutout](https://docs.godotengine.org/en/stable/tutorials/animation/cutout_animation.html)、[CanvasItem](https://docs.godotengine.org/en/stable/classes/class_canvasitem.html)
4. **接缝修补与层级是不同问题。** Harmony 官方解释 Auto-Patch 利用分离的线稿和填色遮住关节内缝，也说明跨 Z 深度的关节需要更完整的补片系统。本项目 PNG 线稿、纸纹和铜钉已烘焙在一起，不能照搬节点名称或盖一个大圆就宣称获得同样效果。[Toon Boom：Auto-Patch](https://helpcentre.toonboom.com/hc/en-ca/articles/45598439632275-How-does-the-Auto-Patch-node-work)
5. **遮罩必须限制作用域。** Spine clipping 明确规定起止 slot，指出自交无效及运行时成本问题。这里借鉴“明确遮谁、在哪结束”，不表示已接入 Spine，也不把其 CPU 实现的开销结论直接套到 Godot 上。[Spine Clipping](https://en.esotericsoftware.com/spine-clipping)

## 三、当前实现核查

读取了两个角色当前 `puppet.json`、v3–v5 绘制代码和 v5 动作接触表。可复查结果在 `gunforge/games/g01/reports/art/T07/revisions/A2j/current_occlusion_audit.json`，由 `pipeline/art/audit_character_occlusion.py` 直接读取当前绘制清单产生。

已确认的结构性问题：

- `t05_puppets.py` 固定设定两条上臂 z=3、躯干 z=5、两条前臂 z=6、头 z=7；v3–v5 没有针对姿态的前后状态。上臂在身后、前臂在身前在部分姿势可以成立，但不能覆盖全部求助、鞠躬和交叉动作。
- 两条腿、两条上臂、两条前臂分别存在相同 z，靠输入列表稳定排序区分。结果可重复，但列表顺序没有表达“哪一侧在前”的设计依据。
- 前臂原图含手；求助时才裁旧手并加新掌。袖口、掌部、关节盖片没有统一、局部化的像素归属规则。持物手也没有独立的手后部/前指遮挡契约。
- 关节补片连铜钉被合并进原部件；小腿、鞋、脚踝补片又从同一图像分出带重叠区域的绘制项。这是重复轮廓、纸纹叠色和补片外露的风险，不能靠关节中心重合排除。是否每一处都已产生可见错误，仍需逐帧像素证据。
- 救援合成按 `z <= torso.z` / `z > torso.z` 一刀切为墨前/墨后。无法表达“墨贴在衣服上，而某一只手、衣领、持物遮住其中一部分”的局部关系。
- 卖糖葫芦居民在 v5 将整个道具放到持物手前臂下方；老板仍把整个道具放在上方。两者都不是通用抓握模型：握住的物体应能处在手掌后部与前方手指之间。

因此本轮撤回“人物遮挡已经合格、可以只等进入 T08 的阶段选择”的判断。此前数值动作检查仍只证明它原先声明的连接、角度等范围，不被追溯改成遮挡检查。

## 四、基础约定

### R01：左右、远近与前后分开命名

- `anatomical_left/right` 只指角色自身左右；当前旧 `_l` 对应画面左、角色自身右，旧 `_r` 对应画面右、角色自身左，仅在当前绑定朝向成立，保留兼容映射。
- `near/far` 指相对镜头；`front/behind_torso` 指相对躯干。不能由 `_l/_r`、x 坐标、旋转角正负推导。
- 两个角色分别标注当前三分之四机位的远近肩、远近髋与可见侧。未标注不允许默认画面左一定更近。
- 当前试做先限制在既有机位，不做未准备附件的完整转身。镜像是独立朝向变体，需复查手掌、持物侧和非对称服饰。

### R02：十个运动部件不等于十个绘制槽或十张 PNG

保留原十部件的运动骨架关系，增加绘制槽不增加人体骨骼。一个前臂骨可以同时驱动袖身、袖口前沿和手；一个躯干骨可以驱动衣服主体、领口前沿和装饰。

最低拆分按实际遮挡需要决定：

- 躯干主体、需要盖住颈根/肩根的衣领或肩部前沿；不能将完整躯干重复画一遍当“前沿”。
- 上臂袖身、前臂袖身；每只手独立姿态附件，需要时有前指片和后掌片；袖口前沿可独立，但不得把未裁掉的原手留在袖身里。
- 大腿、小腿、鞋；如果脚踝要独立转动，鞋必须有明确边界，不能让整只鞋在小腿片和鞋片里各出现一次。
- 铜钉/装饰作为可辨认的单独所有者，或者只烘焙在一个指定片上。每个关节只能出现一枚设计中的铜钉。
- 道具默认整体；只有物体本身还需穿过其他层时才拆前后片。拆出的所有片使用同一个物体变换，不允许各自漂移。

每个槽登记 `slot_id`、驱动骨、局部锚点、绑定朝向、允许附件、像素所有权、遮罩作用域及所属排序组。旧 PNG 先归档；所需隐藏区域不存在时应补画，不能从有轮廓的边缘硬拉伸。

### R03：按姿态编排局部顺序，不套用人体通用 z 表

记号 `A < B` 表示 B 画在 A 上方。只有发生重叠时，这条关系才产生实际遮挡。

- **肩根：** 后方手臂根部 < 躯干；前方手臂的袖身可以覆盖躯干，但根部仍由限定区域的衣服肩沿盖住。不能让整张躯干盖住近侧整条上臂。
- **颈根：** 颈根 < 衣领前沿；脸、头发、帽子是否被手遮住由姿态决定。禁止把“头始终最大 z”当成规则。
- **袖口：** 伸入袖口的腕根/后掌 < 袖口前沿；露在袖口外的指掌保留完整轮廓。需要局部裁切时用袖口遮罩，不能让整只手都埋进整张袖身。
- **肘部：** 为当前可见折叠方向选定内缝隐藏范围，袖身有足够的隐藏延伸；铜钉只画一次。不是一律规定“前臂永远盖上臂”，也不是“盖片永远全场最前”。
- **腰/腿：** 臀腿上端 < 衣摆/围裙对应前沿；交叉处哪条腿在前必须由姿态指定。无前后跨越的行走保持当前三分之四朝向基线，不能随每步左右摆动自动换层。
- **抓握：** 后掌/后指 < 被握物 < 前指/拇指片，袖口仅盖腕根。糖葫芦保留已确认握点与整体朝向，只改变接触处显示关系；录像带盒采用它自己的握持附件，不套用糖葫芦裁切形状。
- **纸面附墨：** 墨附着于明确的衣服表面；手、袖口或道具经过其前方时按绘制结果扣除不可见墨。不能把全部 z 大于躯干的项无差别当同一前景组。

上述是局部关系，须在具体角色的姿态中落实。若出现 A 必须在 B 前、B 又在 A 前的循环，说明单一整片不能表达当前穿插：拆为局部绘制片、换姿态附件或重排动作，禁止靠随机排序消除循环。

## 五、动画怎样换层才稳定

### R04：少量命名状态，固定且完整的绘制清单

每段动作至少声明 `view_id`、`occlusion_profile` 和附件集合，profile 由编排决定；`SIDE_BASE`、`FREE_ARM_FRONT`、`FREE_ARM_BEHIND`、`HAND_OVER_FACE` 等只是可选名称，不代表每个动作都必须切换。

- 静态呼吸、探身若没有跨越关系，整段保持一套顺序。
- 求助中若手臂始终在躯干前，抬起和放下都不换整臂前后；用肩根和袖口的局部规则解决接缝。
- 从背后拿物到身前，才需要显式跨越事件：先让手沿外轮廓绕出，或在被衣服完全遮住时换层，再进入身前。
- 手遮住脸或跨腿等关系确实改变时，标记独立状态。没有可用侧面/缩短附件就限制动作轨迹，不能把正面片旋转成任何视角。

### R05：离散切换，连续动作；同帧提交

关节运动连续插值；slot 顺序、可见附件、mask 所属关系使用离散关键帧，不能插值 z、不能随机排序，也不能在角度阈值两侧逐帧抖动。

切换点选择在两片不重叠、交叉边界吻合或变化被真正遮住的位置。仅有“单帧看不见”仍不足，切换前后都必须看连续播放。实在无法隐藏的穿插，补过渡姿态或调整轨迹，不能把突跳解释成剪纸风格。

同一采样时刻先计算完整骨架姿态，再一次性确定绘制 profile、附件和局部 mask，最后渲染。禁止先换深度、下一帧才换掌面。角色内部顺序使用明确完整列表或无环约束图的确定性排序；无约束项目仍需明确的稳定 ID 次序，不能依赖文件遍历。

### R06：可回放、可跳转，不靠“上一帧切过”

状态由绝对动作时间确定，关键帧区间采用 `[开始, 结束)`。动作跳转、重播、循环、反向采样和暂停恢复，都要能直接重建当时 profile，不能只靠逐帧触发回调。

混合动作必须有一个明确的遮挡状态所有者。前后关系相容才混合关节曲线；不相容时走预先编排的过渡，附件与顺序统一提交。简单按混合权重 0.5 切换仍可能穿帮，不能作为默认验收策略。循环的最后和第一状态、附件及层级也必须闭合。

## 六、像素、遮罩与命中使用同一份结果

### R07：接缝有足够隐藏量，外轮廓只有一个所有者

肩、肘、腕、膝、踝的内部重叠量由该角色全动作扫掠确定，包含最小显示尺寸及过滤影响；不凭空给所有角色固定一个圆补片半径。极端姿态若不能覆盖，就改图或缩小动作范围。

原手/鞋仍在图里时，新增附件必须先明确移除其旧可见区域。拆同一片得到的多个绘制项不能让同一条外轮廓、纸纹或铜钉重复合成。不可见内部允许合理重叠，透明边缘则需按实际渲染采样核对。

如果用软遮罩拆分，不能仅断言“两张 mask 相加等于一”就宣称 source-over 合成与原图一致；半透明边缘、预乘和遮挡顺序会影响结果。必须在黑/白/当前背景上比较拆分前后的重组，并检查实际缩放和 GPU 过滤。边缘算法/容差尚未标定，本规则不宣称它们通过。

### R08：mask 必须有明确目标，接缝遮罩不参与伤害规则

每个遮罩声明坐标空间、驱动骨、被裁 slot、起止范围和版本；肩根的 mask 不能误裁手指，袖口的 mask 不能裁掉道具上的果实，关节补片不能遮住脸。mask 与被驱动图像在同一时刻、同一变换下采样。

正常画面、附墨画面、保护区和可见命中区都由同一份最终绘制清单生成，禁止普通预览正确而救援另走旧阈值分层。

附墨的可见贡献按其上方实际遮挡层的 alpha 扣除：`visible_ink_alpha = clipped_ink_alpha × ∏(1 - occluder_alpha)`，坐标与过滤保持一致。半透明时需要使用已约定的命中阈值，不能把这个可见贡献公式本身当成可攻击判定。人体始终保护；可见墨有效半径、6 像素边界、HUD 和同屏排布按原要求重测，不能为保命中面积让墨穿过手臂显示。

## 七、接入当前 Python 预览与 Godot 的办法

先让 `drawables()` 产出带语义槽名的单份绘制清单，普通预览和救援合成都消费它。骨架仍计算世界变换，绘制槽引用骨架，不再由 `part.z` 自动决定所有动作。

数据应分为：不可变资产描述（槽、附件、像素/遮罩所有权）、按角色视角的默认 profile、按动作的离散 profile 轨道、运动曲线。模板示例在同目录 `CHARACTER_OCCLUSION_CONTRACT_A2j.yaml`；它故意不提供虚构的角色基线或 mask 坐标，补齐前不能启用。

Godot 后续建议把视觉 slot 放在角色自己的排序根下，骨架只提供变换；视觉 slot 使用统一、已解析的整数顺序，关闭角色内部 Y-sort。若视觉 slot 共享同一父级与基准 z，可统一使用相对 z；若分散在不同骨架父级，必须核算最终 z，不能直接抄 Python 的 5.9/6。Godot `z_index` 为整数，`z_as_relative` 默认累加父层级。角色和场景/HUD 的排序另行明确，角色内的局部修正不能改变场景遮挡。[CanvasItem](https://docs.godotengine.org/en/stable/classes/class_canvasitem.html)

这只是接入设计；当前没有相应 Godot 通过证据，不借本规则扩建整套游戏框架。

## 八、修正顺序及验收

1. **先定资产边界：** 为两人物分别标远近、肩/颈/袖口/衣摆边界；列出每张原 PNG 已烘焙了哪些手、鞋、铜钉。先处理重复画出的像素，再谈排序。保留造型和旧版来源。
2. **先修一条完整链：** 卖糖葫芦居民的肩—肘—腕—手、另一侧抓握及衣摆—腿。静态下垂、举臂、最大折肘、横过胸前、手靠脸、感谢鞠躬；每姿势附简明前后标注，再看连续过渡。老板以自己的夹克袖口和盒子单独落规则。
3. **再接入全部动作：** 普通及附墨状态都覆盖，包括起止、极值和所有换层点前后；对新增深度状态的转入转出做检查，而不只测已有动作的正中间一帧。
4. **自动检查只证明明确项目：** 槽位有效且不重复、关系图无环、所有 active slot 排序完整、每槽至多一个姿态附件、不得双手/双鞋/重复铜钉、像素所有权和作用域有效；同一时刻顺序采样与随机跳转结果相同，循环闭合，混合过渡无遗留状态。
5. **必须看图：** 100% 源图看接缝和重复轮廓，实际最小尺寸看可读性，正常速度及半速看跳层/闪边。检查“该在前的区域是否真的挡住后片”，不能只看配置写了 front。机器生成顺序正确但遮挡参考未标注时，应保留待审。
6. **保留能拦错的反例：** 整个前臂强制放到身前、把近远腿顺序互换、保留旧手又加新掌、握物盖住所有前指、复制关节铜钉、提前一帧换层、跨动作残留深度状态、mask 误裁脸/道具、被手挡住的墨仍计作可命中。每项必须证明被对应检查拦住；不能靠人工改好截图规避。
7. **最后重跑受影响检查：** 人物动作、附墨可见面积/半径/边界、同屏/HUD、循环及纹理/绘制成本。新增 slot、附件和 mask 会增加开销，不能继续沿用未重算的显存或 draw-call 结论。

只有上述落到实际素材、渲染器并通过复核，才能说遮挡问题修好。本轮完成的是调研、当前实现审计和执行规则，尚未重做人物动画。无需再次确认已认可的场景、点灯、墨怪受击和墨材质；人物新样片就绪后再到相应检查点。
